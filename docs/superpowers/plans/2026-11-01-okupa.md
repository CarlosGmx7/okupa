# Okupa v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Construir Okupa v1: PWA instalable y sin internet de preguntas para parejas, con ~300 preguntas, sesiones guiadas, editor dentro de la app y arquitectura por módulos.

**Architecture:** HTML/CSS/JS vanilla con módulos ES, sin compilación. Un núcleo (enrutador por hash, almacenamiento seguro, componentes UI) carga los módulos listados en `modulos.json`; v1 tiene un solo módulo, `preguntas`. El contenido vive en JSON; lo propio de la pareja en `localStorage`.

**Tech Stack:** HTML5, CSS (custom properties), JavaScript ES2022 modules, Service Worker, Web App Manifest. Herramientas de desarrollo: Python 3 (`http.server` para servir; Pillow para generar íconos). Tipografías Fraunces e Inter (OFL) en woff2.

**Spec:** `docs/superpowers/specs/2026-11-01-okupa-design.md`

## Global Constraints

- Sin dependencias de producción, sin paso de compilación, sin CDN en tiempo de ejecución (todo local para funcionar sin internet).
- Todo texto visible en español colombiano, con tuteo.
- Todo acceso a `localStorage` pasa por `js/nucleo/almacen.js` (try/catch; si falla, la app sigue sin recordar).
- Claves de almacenamiento con prefijo `okupa:<idModulo>:`.
- Texto proveniente de datos o del usuario se inserta con `textContent`, nunca `innerHTML`.
- Ids de preguntas incluidas: `<prefijoCategoria>-NNN`; ids propios empiezan con `n-`.
- Paleta: fondo `#140a0e`, superficie `#24121a`, vino `#6e1f35`, vino claro `#a8344f`, dorado `#c9a45c`, crema `#f3e9dc`, texto tenue `#b9a99c`.
- Respeta `prefers-reduced-motion`.
- Caché del service worker: `okupa-v1`.
- Pruebas: `pruebas.html` servido en `http://localhost:8080/pruebas.html`; pasa cuando `#resumen` dice `0 fallaron`.

## Review Focus

1. Un filtro que deja cero preguntas (categoría con todas ocultas, intensidad máxima 1 en categoría sin suaves) → mensaje "No quedan preguntas aquí" con acción para ajustar, nunca pantalla vacía ni error. (Task 4, Task 8)
2. Al azar con todas las preguntas ya vistas → ofrece "Reiniciar vistas" de esa selección; nunca bucle infinito. (Task 8)
3. Importar un archivo corrupto, de otra app o de versión desconocida → rechazo con explicación, datos existentes intactos. (Task 2, Task 9)
4. Pregunta propia vacía, solo espacios, >500 caracteres o con `<script>` → validación la rechaza o la muestra literal como texto. (Task 9)
5. Vistas, avance de sesión o sesión propia que apuntan a ids que ya no existen (contenido actualizado, pregunta propia borrada) → se ignoran sin romper; la sesión salta esa pregunta. (Task 6, Task 9)

### Task 4: Módulo de preguntas: datos

- Constantes exportadas: `FORMATOS = ['abierta','corta','dilema','postura']`, `SUBTIPOS = ['si_no','escala','esto_o_aquello']`.

- `validarContenido({ categorias, fuentes, preguntas, sesiones })` → `string[]` (errores legibles): ids únicos; categoría y fuente existentes; `formato ∈ FORMATOS`; `profundidad ∈ {1,2,3}`; `texto` no vacío; `corta` exige `subtipo ∈ SUBTIPOS` y `opciones` de longitud 2 para `si_no` y `esto_o_aquello` (para `escala`, `opciones` = `[etiquetaMin, etiquetaMax]`); sesiones referencian ids existentes.
